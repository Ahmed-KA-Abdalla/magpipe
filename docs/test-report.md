# magpipe — test report

Version 0.1, August 2026. Covers magpipe 0.1 at commit `67e133f`.

## 1. Scope

This report describes what the test suite covers, how it is structured,
what it does not cover, and the results of the most recent run.

## 2. Strategy

The suite is arranged in three layers.

**Unit tests** cover each module against synthetic input constructed to
contain a specific defect. They are the majority of the suite.

**Integration tests** run the parser and validator against real
INTERMAGNET extracts committed under `tests/data/`. Synthetic fixtures
test what the specification says; real files test what the service
actually sends. Both are necessary, and the difference between them has
already caught two defects, recorded in section 6.

**Static checks** run in continuous integration: ruff lint and format.

Two properties hold across the whole suite.

**No test performs network access.** HTTP is exercised through a stub
session which returns queued responses and records the URLs it was
given. A suite that reaches the network is slow, fails for reasons
unrelated to the code, and cannot run in CI without credentials or
allowances. The stub also makes retry and backoff behaviour testable,
which a real connection does not.

**No test compares images.** Plot tests inspect the figure object: the
number of axes, the data attached to each line, the text of each label.
Pixel comparison is brittle across matplotlib and font versions, and it
fails in ways that do not indicate a defect. Inspecting the object
catches the failures that actually occur — an element silently dropped,
a baseline applied twice, absent values coerced to zero.

## 3. Test data

**Synthetic fixtures** are generated by `tests/fixtures/_make_fixtures.py`
and committed. Three files: one clean, one containing omitted samples
and missing-value sentinels, and one where an element is never observed.
Generating them rather than downloading them allows each defect to be
placed deliberately, and avoids redistributing licensed data for cases
that do not require real measurements.

**Real extracts** under `tests/data/` are six-hour cuts from definitive
one-minute data for Eskdalemuir and Hartland on 10 May 2024, taken under
an `XYZS` orientation so that the total field comes from an independent
scalar instrument. Each is about 27 kB and carries the INTERMAGNET
acknowledgement as comment records. They are produced by
`scripts/make_sample.py`, and the integration tests skip themselves when
the directory is empty, so the suite passes on a fresh clone before any
download.

## 4. Coverage

| Module | Tests | Statement coverage |
| --- | --- | --- |
| `fetch` | 31 | 100% |
| `parse` | 29 | 94% |
| `validate` | 34 | 99% |
| `plot` | 24 | 96% |
| real extracts | 8 (×2 files) | — |
| **Total** | **134** | **97%** |

Coverage is measured with `pytest --cov=magpipe`. The uncovered
statements are branches in `parse` handling malformed records that the
fixtures do not construct, and defensive paths in `plot` for empty
frames.

Coverage is a measure of what was executed, not of what was verified,
so the following summarises what each module's tests assert.

**`fetch`** — parameter spelling and capitalisation, since the service
returns HTTP 400 without saying which parameter is wrong; date
formatting as plain days; duration rather than end date; rejection of
invalid observatory codes, cadences, publication states, orientations
and over-long spans; cache hits, misses and forced refresh; retry with
backoff on transient failure; no retry on HTTP 400 or 404; rejection of
empty, HTML and non-IAGA payloads; and that a rejected payload is not
written to the cache.

**`parse`** — header extraction and canonicalisation, including
case-insensitive matching; element columns following the `Reported`
header; UTC-aware monotonic index; correct values and dtype; three- and
four-element files; HDZF as well as XYZF; both absent-value sentinels
converted to NaN with counts retained separately; blank lines ignored;
and eight classes of malformed input rejected with an error naming the
offending line.

**`validate`** — each check tested twice, once against data it should
pass and once against data carrying exactly the defect it exists to
detect. Gap runs reported as one interval rather than per sample;
tolerance boundaries in both directions; storm-scale variation not
flagged as spikes; scatter of the magnitude measured at ESK and HAD not
flagged as inconsistency; systematic offset flagged as an error while
isolated excursions are not.

**`plot`** — panel count and ordering; every sample reaching the line;
baseline subtraction centring the series and recording the offset in the
label; absent values remaining NaN rather than becoming zeros; gap
shading present when gaps exist and absent when they do not; residual
computed as scalar minus vector magnitude; comparison overlaying sites
with different absolute fields.

## 5. Results

Latest run, 11 August 2026, Python 3.12 on Windows 11:

    134 passed in 1.74s

Continuous integration additionally runs the suite on Python 3.11 and
3.13, and inside the Docker image.

Validation of the four real files downloaded to date — Eskdalemuir and
Hartland, 10 May 2024, one-minute definitive data, under both `Native`
and `XYZS` orientations — reports no issues at the default thresholds.

Under `Native`, both observatories report elements XYZG rather than
XYZF. G is the provider's own scalar-minus-vector residual, so the
consistency check does not apply and is skipped. This is correct
behaviour but easy to misread: a report showing no issues under a
`Native` orientation reflects five checks, not six.

## 6. Defects found

Two defects were found by running against real data after the unit tests
passed, which is the case for keeping both layers.

**Request construction.** The initial client sent lower-case `request`
and `format`, and ISO 8601 timestamps with times attached. Every request
returned HTTP 400. The unit tests asserted that the parameters were
present but not that they were spelled as the service requires; they now
assert the exact capitalisation and date format.

**Header label matching.** The parser required the label `IAGA CODE` in
that exact form and rejected every real file. Labels are now matched
case-insensitively with whitespace collapsed, the required set is
restricted to the three headers the module reads, and the error lists
the labels that were present.

A third finding was not a defect but a mis-set tolerance. The
scalar/vector consistency check used an assumed 1.0 nT limit on
individual samples, which flagged ordinary instrument disagreement as a
fault. The tolerances were re-derived from measured residuals; see
section 5 of the design note.

## 7. Not covered

- The two scripts under `scripts/` have no tests. They contain only
  composition of tested modules and argument parsing.
- `hdz_to_xyz` is tested against synthetic input only. No real HDZ file
  has been processed.
- One-second data is untested. The client accepts it and enforces the
  service's 31-day limit, but no such file has been retrieved and the
  memory behaviour at 86,400 samples per day is unexamined.
- No test covers observatories outside the UK, so the range thresholds
  are unverified against high-latitude or equatorial data.
- No performance or load testing.
- The Docker image is built and exercised in CI, but no test asserts
  anything about the image beyond the suite passing inside it.

## 8. Reproducing

    pip install -e ".[dev]"
    pytest                                  # unit and integration
    pytest --cov=magpipe --cov-report=term-missing
    ruff check . && ruff format --check .
    docker compose run --rm test            # inside the image

To regenerate the real extracts from scratch:

    python scripts/fetch_data.py --obs ESK HAD --start 2024-05-10 \
        --orientation XYZS --check
    python scripts/make_sample.py data/raw/esk_20240510_1d_minute_best-avail_*.min \
        --hours 6 --label esk_storm
